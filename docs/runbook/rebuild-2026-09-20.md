## Phase 4 — Cluster services

**The ingress decision is settled. See ADR 0008.** ingress-nginx is not
reinstalled; the cluster moves to Gateway API with **Envoy Gateway**, keeping
Flannel. Read the ADR before starting — several things this checklist used to
say were wrong, and the reasons matter.

Order is not free here. Gateway API CRDs must exist before Envoy Gateway, and
before cert-manager, which needs an explicit `--enable-gateway-api` and refuses
to start the feature without the CRDs.

- [ ] **Gateway API standard-channel CRDs.** Standard channel only. Nothing in
      the design needs `TLSRoute` or the experimental channel; if ArgoCD's gRPC
      forces a fallback to passthrough, that is when the experimental CRDs get
      reconsidered, and it is a change to this ADR.
- [ ] **Envoy Gateway.** Pin the version in the manifest, as `core/cni` and
      `core/hcloud` do.
- [ ] **cert-manager**, with `--enable-gateway-api`
      (`config.enableGatewayAPI=true`), plus a **DNS-01 `ClusterIssuer` using
      Cloudflare**. The token is scoped `Zone:DNS:Edit` on `tosak.net` alone.
      One wildcard `Certificate` for `*.tosak.net`, issued into the `gateway`
      namespace. It does not cover the apex; no host uses the apex.
      **This issues before the load balancer exists** — that is the point of
      choosing DNS-01, so do it in this order and not after.
- [ ] **The `gateway` namespace and one shared `Gateway`.** One HTTPS listener
      with the wildcard certificate, one HTTP listener. `allowedRoutes` names
      the namespaces permitted to attach: `argocd`, `authos`, `doma`.
- [ ] **`EnvoyProxy` carrying the Hetzner annotations.** Under
      `provider.kubernetes.envoyService.annotations`, taken from the deleted
      `core/load-balancer/load-balancer.yaml`: `name: tosak-lb`, `type: lb11`,
      `location: hel1`, `use-private-ip: "true"`,
      `private-subnet-ip-range: 10.0.4.0/24`, `private-ipv4: 10.0.4.2`,
      `uses-proxyprotocol: "true"`, `algorithm-type: round_robin`.
      **Drop the mqtt port 1883** — wasteio is out of scope (ADR 0003).
- [ ] **`ClientTrafficPolicy` on the Gateway**, carrying three things that must
      land together:
      1. `enableProxyProtocol: true`. The Hetzner annotation and this setting
         are two halves of one thing. PROXY headers arriving at a listener that
         does not expect them break **every** connection.
      2. `clientIPDetection.customHeader: CF-Connecting-IP`. Every host is
         proxied by Cloudflare, so the PROXY-protocol address is a Cloudflare
         edge address, not the visitor's.
      3. `tls.clientValidation.caCertificateRefs` holding the **per-zone**
         Cloudflare origin-pull certificate, with Authenticated Origin Pulls
         enabled on the zone. Without it the header in (2) is forgeable by
         anyone who finds the origin address. Cloudflare's *shared* origin-pull
         certificate does not do this job — it is the same for every Cloudflare
         customer.
      🔴 **Do not reach for a `SecurityPolicy` IP allowlist instead.**
      `clientCIDRs` matches the *detected* client address, so with (2) set it
      checks the forgeable header against itself. ADR 0008 explains why that is
      worse than no lock at all.
- [ ] **Delete load balancer `6579148`**, let the CCM build a fresh one from
      the `EnvoyProxy` annotations, then update the four Cloudflare A records
      to its new address. Low risk: all five hosts resolve to Cloudflare edge
      addresses, so this is an origin change behind the proxy and not a
      propagation event for visitors.
- [ ] **Delete the old ingress entirely:** `core/ingress-controller/` (both
      classes — `private-nginx` had no consumer left but the Longhorn UI, which
      ADR 0005 removes), `core/load-balancer/load-balancer.yaml`,
      `core/whoami-test-ingress.yaml`, `core/longhorn/`.
- [ ] **Convert the `Ingress` objects to `HTTPRoute`.** `ingress2gateway` does
      the mechanical part; the output needs reading.
      - **Delete every `URLRewrite` filter it emits.** The three
        `rewrite-target: /` annotations were **inert** — ingress-nginx skips the
        rewrite when the path equals the target, and every path in those three
        objects is `/`. Gateway API passes the path through unchanged, which is
        the live behaviour. `/duster` on `authos-demo.tosak.net` must reach
        Duster with its path intact, and that is now the default.
      - `argocd` loses passthrough: set `argocd-server` to `--insecure`,
        terminate at the Gateway, and put `appProtocol: kubernetes.io/h2c` on
        the `argocd-server` Service port so the CLI's gRPC still works.
        **Acceptance test: `argocd login` and `argocd app list` over
        `argocd.tosak.net` must pass.** If they do not, the fallback is
        passthrough, which costs the experimental CRDs — and that is a change to
        ADR 0008, not a quiet fix.
      - Apply routes for `argocd`, `authos`, `authos-api`, `authos-demo` and
        `doma` only. Convert and commit `imaps` and `wasteio`, but do not apply
        them: their manifests stay in the repo unsynced (ADR 0003).
- [ ] ~~Longhorn~~ — removed entirely (ADR 0005). No install, no ingress, no
      `basic-auth` secret, no host prerequisites.
- [ ] CNPG operator, `tosak-pg-cluster` on `storageClass: hcloud-volumes`,
      databases `authos` and `doma` only. **First real volume attach in the
