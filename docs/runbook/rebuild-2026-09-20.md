## Phase 1 — Terraform restructure. No applies yet.

- [x] Split `infra/` into `shared/`, `control-plane/`, `workers/` (ADR 0002).
      Cross-module references are hcloud data sources **by name**.
- [x] `shared/` manages the network, the four subnets and the firewall — and
      also the ssh key and the primary IP, which were previously `data`
      sources. ADR 0002 assigns both to `shared/`; left unmanaged, the repo
      could not rebuild into an empty Hetzner project.
- [x] `control-plane/` manages only `k8s-cp`, with `prevent_destroy = true`,
      `delete_protection = true`, `rebuild_protection = true`.
- [x] `workers/` manages only the worker map. `var.node_suffix` deleted with no
      replacement — worker names are stable: `k8swk1`, `k8swk2`, `k8swk3`
      (ADR 0005). No `create_before_destroy`: Hetzner names must be unique
      among live servers.
- [x] Configure the `s3` backend against R2, `use_lockfile = true`, one key per
      module — written in each `backend.tf`, and initialised. R2 accepted
      `region = "auto"`.
- [x] **Import** the surviving network, subnets, firewall, ssh key and primary
      IP into `shared/`. They exist; creating them would be wrong. Ran
      `infra/shared/import.sh` — state-only, idempotent. All eight addresses
      are in `tfstate/shared.tfstate` on R2. State locking via `use_lockfile`
      is confirmed working against R2.
- [x] `git rm --cached` the tfstate files and the 39 MB of vendored provider
      binaries under `infra/.terraform/`; both added to `.gitignore`.
      Per-module `.terraform.lock.hcl` files stay tracked.
- [x] Verify the import. The check is **zero create, zero destroy, zero
      replace** — not literally "no changes".

      Result: **`Plan: 0 to add, 2 to change, 0 to destroy.`** Gate passed.
      Both changes are the expected ones, and **neither has been applied**:

      1. `hcloud_primary_ip.cp_authos_ip` — `delete_protection` false → true.
      2. `hcloud_firewall.authos_cluster_firewall` — the port 22 rule is
         removed, because `allow_public_ssh` defaults to false. The WireGuard
         rule renders as a remove-and-add pair; that is how Terraform diffs a
         set of blocks when one member leaves, and its contents are unchanged.

      Phase 2 needs SSH, so it sets `allow_public_ssh = true`, which puts the
      port 22 rule back pinned to the workstation's current address. Details in
      `infra/README.md`.
- [x] `control-plane/` and `workers/` backends initialise against R2. Neither
      holds state yet; they own nothing until Phases 2 and 3.

- [x] Apply the two changes. Authorised by the operator after the gate passed,
      so `shared/` now matches its configuration. `Apply complete! Resources:
      0 added, 2 changed, 0 destroyed.`

      **Verified directly against the Hetzner API, not from the apply output:**
      the firewall now carries the WireGuard rule alone, with `0.0.0.0/0` on
      UDP 51820 intact — confirming the remove-and-add pair in the diff was
      only Terraform redrawing the set. Primary IP `46.62.209.249` reports
      `protection.delete = true` and `auto_delete = false`.

      `terraform plan` then returned **`No changes.`** with
      `-detailed-exitcode` 0.

**Phase 1 is complete and converged.** Port 22 is now closed cluster-wide.
Phase 2 must set `allow_public_ssh = true` in `shared/` and apply it *before*
trying to reach the new control plane, or the SSH will hang.
